# P6 启动器与分发 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 零技术用户双击一个几 MB 的启动器：首次运行在浏览器里显示下载进度（Node 运行时、ffmpeg、Chrome Headless Shell、本地模型、配乐字体、应用本体），断点续传 + 哈希校验 + 国内镜像；完成后启动本机工作台并自动跳转；之后秒开。附 README 中英双语、macOS 签名公证脚本与 Windows 包。

**Architecture:** 启动器用 Rust（单文件、无 webview）：内置一个只监听 127.0.0.1 的小 HTTP 服务提供「安装进度页」，用系统默认浏览器打开；后台按清单（`manifest.json`，随启动器发布）逐项下载到应用目录（macOS `~/Library/Application Support/Mingzhi`，Windows `%LOCALAPPDATA%\Mingzhi`），支持 HTTP Range 续传、sha256 校验、多镜像按序回退；全部就绪后用内置的 Node 启动 `server.mjs`（P5 服务的打包产物），把进度页跳转到工作台。应用本体（服务端打包 + 前端构建 + 生产依赖，含平台原生模块）由 CI 按平台打包成 tar.zst 发布到 GitHub Releases。

**Tech Stack:** Rust 1.94（`tiny_http`、`ureq`（rustls）、`sha2`、`zstd`/`tar`、`open`、`serde_json`）、GitHub Actions（macOS arm64/x64、Windows x64 构建）、esbuild（服务端打包）、Vite（前端）

**Spec:** `docs/DECISIONS.md`「分发与运行」全部条目（启动器、技术栈、签名、最低配置、更新、界面语言）与 P2/P3 验收里记录的下载问题（Node fetch 不走代理、GitHub 在国内不稳定）。依赖 P5 完成。

## Global Constraints

- 平台：macOS + Windows，零技术用户，全程不开终端
- 启动器几 MB；首次下载 Node 运行时 / ffmpeg 静态版 / Chrome Headless Shell / 本地模型（断点续传 + 哈希校验 + 国内镜像），起本机服务并自动打开浏览器；之后秒开
- 签名：macOS 买 Apple 开发者账号做签名 + 公证；Windows 暂不签，README 说明 SmartScreen 放行方式
- 最低配置：Apple M1 或 8 核 x86、16GB 内存；低配先出 540p 预览
- 更新：查 GitHub Releases，用户点击才更新；默认不收集任何数据
- 界面只做中文；README 中英双语；README 注明 Remotion 对 >3 人公司需购买其商业授权；不含任何 key，注册链接不带邀请码
- 本机现状：只有「Apple Development」证书（不能用于分发公证）→ 签名公证脚本读环境变量（`APPLE_SIGN_IDENTITY`、`APPLE_ID`、`APPLE_TEAM_ID`、`APPLE_APP_PASSWORD`），缺失时跳过并提示
- 开源前必须清理：`docs/design/assets/frame_*.jpg`、`speaker_bottom.jpg` 及设计稿截图里含真人的图（改写历史前须用户确认）
- 代码注释、界面文案、commit 中文；commit `<type>: <描述>`，无署名行

### Task 1: 下载清单与镜像

**Files:** Create `launcher/manifest.schema.json`、`scripts/build-manifest.mjs`（读取 P1–P3c 的模型/素材清单 + ffmpeg/Node/Chrome 版本，生成 `dist/manifest.json`）；Test `tests/manifest.test.ts`

- 每项：`{ id, kind: 'node'|'ffmpeg'|'chrome'|'model'|'asset'|'app', platform: 'darwin-arm64'|'darwin-x64'|'win32-x64'|'any', sha256, size, dest, unpack?: 'tar.gz'|'tar.xz'|'zip'|'tar.zst', urls: string[] /* 按优先级，国内镜像在前 */ }`
- 镜像：Node → `https://npmmirror.com/mirrors/node/v22.x/…` 优先、`https://nodejs.org/dist/…` 其次；Chrome Headless Shell → `https://cdn.npmmirror.com/binaries/chrome-for-testing/<ver>/…` 优先、`storage.googleapis.com/chrome-for-testing-public/…`；GitHub 资源 → GitHub 直链 + 用户可配置的代理前缀（设置项，不内置第三方代理）；模型 → modelscope / hf-mirror 若有同名文件则优先
- 版本钉死且 sha256 由脚本实际下载计算（脚本带 `--verify` 重新校验）

### Task 2: Rust 启动器核心（下载、续传、校验、解包）

**Files:** Create `launcher/Cargo.toml`、`launcher/src/{main.rs,download.rs,unpack.rs,paths.rs,manifest.rs}`；Test `launcher/tests/*.rs`（本地起 tiny_http 模拟服务器：Range 续传、坏哈希重下、首个镜像 404 回退第二个）

- 并发 2；每项下载到 `.part`，带 Range 续传；完成后 sha256，不符删除重下（最多 3 次，换镜像）；解包到临时目录再原子改名
- 尊重 `HTTPS_PROXY`/`HTTP_PROXY` 环境变量与系统代理（macOS `scutil --proxy` 读取）

### Task 3: 安装进度页与启动流程

**Files:** Create `launcher/src/{server.rs,ui.html}`（进度页：G1 视觉 token，逐项进度条、总进度、速度、失败重试按钮、镜像切换、代理前缀设置）；`launcher/src/run.rs`（就绪检查 → 用内置 Node 启动 `app/server.mjs`，等待 `/api/status` 就绪 → 进度页跳转；端口占用顺延；启动器退出时结束子进程）

- 二次启动：所有项就绪且哈希缓存一致时直接起服务并打开浏览器（目标 < 3 秒）
- 低配检测（CPU 核数 < 8 或内存 < 16GB）：设置 `MINGZHI_PREVIEW_540=1` 给服务，抠像先缩到 540×960

### Task 4: 应用本体打包

**Files:** Create `scripts/bundle-app.mjs`、`.github/workflows/release.yml`；Modify `package.json`（tsx 移到 dependencies）

- 应用本体**不做单文件打包**（服务端多处按源码目录定位 render/、assets/、web/dist，分段渲染的缓存指纹读 src/）：`app/` = 仓库的 `src/`、`render/`、`assets/`（不含大文件）、`web/dist`、`package.json`、`pnpm-lock.yaml` + `pnpm install --prod --frozen-lockfile` 得到的 `node_modules`（含平台原生模块）；启动命令 `node --import tsx src/server/index.ts`；打成 `mingzhi-app-<platform>.tar.zst`
- Chrome Headless Shell 由启动器下载到 `app/node_modules/.remotion/chrome-headless-shell/<platform>/`（与 Remotion 自己的目录结构一致，含 `VERSION` 文件），服务端无需改代码
- CI 三平台矩阵（macos-14 arm64、macos-13 x64、windows-latest）：构建 web、打 app 包、构建启动器、计算 sha256、生成 manifest、上传 Release（草稿）

### Task 5: 签名、公证与 Windows 包

**Files:** Create `scripts/macos-sign.sh`（`codesign --options runtime --timestamp`、`xcrun notarytool submit --wait`、`xcrun stapler staple`；读环境变量，缺失时跳过并打印说明）、`launcher/windows/mingzhi.rc`（图标、版本信息）；Windows 产物为单个 `Mingzhi.exe`（启动器）+ 可选 zip
- README 写 SmartScreen「更多信息 → 仍要运行」放行步骤与截图位置说明

### Task 6: 更新检查与 README

**Files:** Create `src/server/update.ts`（查 GitHub Releases 最新版本，工作台右上角提示「有新版本」，点击才下载新启动器/新 app 包）、`README.md`、`README.en.md`、`docs/acceptance/p6.md`
- README：一句话介绍、成片示例（不含真人或经授权的示例）、下载与首次运行、可想 AI 注册与填 key（链接 `https://kexiangai.com`，不带邀请码）、最低配置、隐私（音频不出本机、默认不收集数据）、常见问题（代理、SmartScreen、Gatekeeper）、许可证 MIT + Remotion 商业授权说明 + 第三方素材许可（HoliznaCC0 / Kenney CC0 / 字体 OFL / RVM GPL-3.0? 需核对 RVM 模型权重许可后写明）、开发者指南（pnpm、fetch-models、fetch-assets、测试）

# P2 换背景与人像中间件 · 验收记录（2026-10-15）

## 1. 结论
`pnpm mingzhi edit 口播.mp4 --bg <预设id|图片路径>` 或 `--bg-prompt "一句话"` 可在本机抠像换背景（虚化 + 色温/亮度匹配），`project.json` 记录背景与人物取景框，供 P3 排「下半屏人像」。141 个测试全部通过；5 个任务逐个审查，整分支终审（opus）后修复两项 Important 并复审通过。

## 2. 真实素材
| 素材 | 背景 | 结果 |
|---|---|---|
| 生口播 132 秒 360×640（`work/raw1/raw1.mp4`） | 预设「书房」 | 3666 帧全部抠完；头发边缘干净；人物色调随背景转暖；取景框 `{top:0.078,bottom:1,left:0,right:1}` |
| 测试样片 19 秒 | 一句话「明亮的现代办公室，落地窗，绿植」 | 可想生图返回 1024×1536（`2:3` 有效），全流程 78 秒，约 ¥0.2 |

## 3. 性能（终审实测，独立负载下）
- RVM 推理分辨率固定为长边 512：360×640 与 1080×1920 推理都约 41–46ms/帧
- 端到端：360×640 约 20 帧/秒；1080×1920 约 12 帧/秒（2 分钟 1080p 口播约 5 分钟）
- 冒烟时记录的 9.7 帧/秒是多个 agent 同时跑测试抢占 CPU 所致
- 内存：360×640 常驻约 295MB；1080×1920 峰值约 820MB
- CoreML 执行提供器比 CPU 慢（9.4 vs 12.8 帧/秒），只用 CPU

## 4. 终审修复
- 背景参数、抠像模型、一句话生成所需 key 在流程开头校验（之前要等识别与付费模型跑完才报错）
- `parseProbe` 按旋转元数据返回显示尺寸（iPhone 竖拍常见 1920×1080 + -90°）
- 剪切时统一成偶数宽高（奇数尺寸原片之前会让 libx264 报错）
- 色温增益的白平衡与亮度分开限幅（之前 10 张预设里 6 张的白平衡被限幅吞掉）
- 抠像中途进度、ORT 会话释放、可想任务 `id: null`、下载失败清理 `.part`

## 5. 已知限制 / 延期
- 桌面等与人相连的前景物体会被一起抠出（RVM 模型局限）；下半屏取景会裁掉大部分
- 人物抠像没有自动化测试素材（不能把真人素材提交进开源仓库），靠验收实跑覆盖
- Node 内置 fetch 不走系统代理：`pnpm fetch-models` 在代理环境下需 `NODE_USE_ENV_PROXY=1`；P6 启动器要用国内镜像
- 低配机（M1 / 8 核）1080p 抠像预计 6–8 帧/秒；P6 落实「低配先出 540p 预览」
- `--bg` 写成与预设同名的本地文件时按预设处理

方法：

- **联系表**：每条片子均匀抽帧（长片每 2s 一帧，短片每 0.5s 一帧），左上角标时间码。
- **定量**：把每帧缩到 108×192 灰度、每秒 5 帧，只看上半屏（卡片区，y < 84/192，避开压在分界线上的字幕），统计：
  - 硬切：相邻 0.2s 平均差 > 25；
  - 静止：相邻 0.2s 平均差 < 0.8，连续超过 3s 记为一个「死段」；
  - 空白率：6×6 像素块标准差 < 2.5 的比例；
  - 色彩丰富度（Hasler-Süsstrunk）、饱和度、纹理帧比例（纹理帧近似看作「摄影级画面」）。
- **结构数据**：读 `project.json` 里的分镜、B-roll 记录、自检分、音频；同时读代码 `src/storyboard/*`、`src/broll/*`、`render/*`、`src/audio/plan.ts`、`src/qa/visual.ts`。

### 2.2 行业公认的观察（没有逐条公开出处，作为导演经验给出，P7 落地前建议人工对照原片核实）

- **调色**：全片一个统一的色彩世界（偏暖或中性、高光柔和、低饱和、肤色准）；B-roll 和主画面用同一套 LUT；细颗粒加轻暗角，去掉「数码感」。
- **空镜与微距**：产品和实物用浅景深微距、滑轨慢推或环绕；空镜是**有信息的画面**（拍的就是口播里说的那个东西），不是氛围填充。参见 [MediaStorm.com 关于 B-roll 的说法](https://www.mediastorm.com/blog/?p=19714)：「B-roll 不应只是凑数的填充素材」（这是美国同名纪录片公司，不是影视飓风，仅作通用参考）。
- **速度变化**：升格慢动作加曲线变速，在剪点前后加速或减速，形成「呼吸」。
- **信息图**：大号数字滚动、图表逐条生长、关键词放大；**一个组件跟着口播逐步展开**，而不是一句话换一张卡。
- **转场**：以硬切为主，动作匹配或形状匹配，偶尔用遮罩擦除或甩镜模糊；转场一定配声音。
- **声音**：whoosh、hit、riser、底噪分层，音效和画面动作逐帧对齐；配乐在段落切换处换气或转调；J-cut/L-cut 让声音先进。
- **字幕**：克制、统一、不和画面信息重复；关键词才做强调。
- **结尾**：有品牌片尾或标志性收束，不在半句话处截断。

## 5. B-roll 专项

### 5.1 现状：B-roll 怎么来的

| 环节 | 现状（代码） | 问题 |
|---|---|---|
| 谁决定 | 分镜模型（`gemini-3.5-flash`，low）在生成分镜时顺带在 hook、photo、browser 卡里写 `visual`（`src/storyboard/generate.ts` 规则 7） | B-roll 是**卡片的附属字段**，不是独立的「画面规划」；模型主要在想字卡，配图是顺手写的。try2 的 22 个镜头里只申请了 3 次素材 |
| 来源优先级 | 截图 > 生图 > Pexels（用户自备 key）> 搜索 > Seedance（只给钩子，全片最多 1 条）（DECISIONS 第 4 条，`src/broll/fulfill.ts`） | 实拍视频素材**完全没有**（Pexels 只搜图，`per_page=1&orientation=square`，取第一张）；没有 Pixabay、Wikimedia |
| 检索 | 截图：`gpt-5.6-luna` web_search 找 URL，再用无头 Chrome 1080×1350 截图；生图：GPT-Image-2.5-Flare 1:1 1k，后缀 `no text, no watermark` | 生图失败才回退 Pexels，**只取 1 个候选**；没有任何「看图挑图」环节 |
| 筛选 | 无 | 语义错配（README v3：说手机，图里是笔电）和复用（钩子图被二次使用）都发现不了 |
| 呈现 | `Photo.tsx`：上半屏 1080×960 cover，6 秒推近 6%，左下角玻璃标签；`Hook.tsx`：图片压暗 55% 做底；`ShotVideo`：4 秒循环 | 只有「上半屏贴图」一种呈现；没有全屏插入、画中画、视差、变速、调色、颗粒 |
| 授权 | `BrollAsset.source` 只记来源类型和 url | 没有作者、许可证、署名要求，也不提示用户 |
| 失败兜底 | 生图失败 → photo 卡丢弃变人物全屏；hook 退化成纯文字 | try2 的网络失败直接导致**全片零 B-roll**，没有离线兜底（本地素材库、自绘图形） |

### 5.2 为什么「审美还差一点意思」

1. **画面不承载信息**：素材是「主题氛围图」（未来办公室、机器人、笔电绿植），不是「口播里那个具体的东西」。观众看到图，学不到新东西。
2. **陈词滥调**：模型生图默认落在 stock 套路上（蓝色全息、机器人、笔电咖啡）。
3. **单一呈现**：所有素材都被关在上半屏、加同一个 6% 推近，像 PPT 配图，不像剪辑。
4. **色彩不统一**：素材之间、素材和人物之间没有统一的影调。
5. **没有挑选**：只取第一个结果，也没有视觉审稿；人工剪辑师会从 20 个候选里挑 1 个。
6. **没有节奏角色**：B-roll 在剪辑里的作用是**打断说话人画面、制造呼吸和信息兑现**（S6「口播精剪与 A/B-roll 协同」）；现在 B-roll 只是卡片背景。

### 5.3 方案：让模型「上网找对应素材」丰富画面

总体流程（新增 `src/broll/plan.ts`、`sources/*`、`select.ts`、`process.ts`、`credits.ts`；与分镜并行或紧随分镜之后）：

```
字幕+分镜 ──► ① 素材规划（视觉节拍表）
              │
              ▼
          ② 多源检索（并行，免费源优先）
              │  Pexels 视频/图 · Pixabay 视频/图 · Wikimedia Commons
              │  官方页面截图（luna web_search 找 URL）· 开放数据→自绘图表
              │  兜底：GPT Image 2 生图 →（可选）Seedance 图生视频
              ▼
          ③ 视觉审片打分（候选拼 3×3 联系表，一次调用）+ 去重
              ▼
          ④ 加工：智能裁切 → 选段/变速 → 统一调色+颗粒 → 运动设计
              ▼
          ⑤ 授权记录 credits.json + 工作台「素材来源」面板 + 发布正文署名
```

#### ① 素材规划：视觉节拍表（Visual Beats）

由 `gemini-3.5-flash`（low）读字幕和分镜，输出与镜头对齐的 beats：

```json
{"beats":[{
  "start": 10.5, "end": 14.3,
  "role": "illustrate | prove | locate | emote | define",
  "kind": "footage | photo | screenshot | chart | ui | generated",
  "subject": "工程师在客户办公室和业务人员一起看屏幕",
  "must_show": ["两人以上", "电脑屏幕", "办公室"],
  "avoid": ["机器人", "全息", "蓝色科技光效", "西方面孔特写"],
  "query_en": ["engineer client office meeting laptop", "consultant explaining screen colleagues"],
  "query_zh": ["驻场工程师 客户现场"],
  "url_hint": null,
  "present": "broll-full | split | pip | overlay",
  "shot_size": "ECU | CU | MS | WS",
  "motion": "push-in | pan-left | parallax | slowmo | static",
  "min_res": [1080, 1920]
}]}
```

规划规则：

- 抽象段落（定义、对比、原因）B-roll 覆盖率不低于 30%；每 15 秒至少 1 个「真实世界」画面（实拍、实物、真实网页）。
- 优先**具体名词**：口播里出现的产品、机构、地点、数字、动作。try2 的例子：
  - 0:10「带进业务现场」→ 现场实拍视频；
  - 0:40「需求清单写在合同里」→ 合同纸张微距；
  - 0:48「3 次 5 次 个位数」→ bigNumber 计数；
  - 0:54「线性的」→ 流程图动画；
  - 1:50「敏之 AI 社区」→ 社区页面截图；
  - FDE 定义 → 用 web_search 找真实的「Forward Deployed Engineer」招聘页截图（需联网核实）。
- 景别交替（不连续两个同景别），role 交替。

#### ② 多源检索（按授权从宽到严，免费源优先，搜索可以并行）

| 来源 | 适合 | 接口要点 | 授权 |
|---|---|---|---|
| **Pexels 视频 / 图片** | 实拍空镜、动作、氛围 | `GET /v1/videos/search?query&orientation=portrait&size=medium&per_page=15`；图片 `/v1/search` 支持 `orientation`、`color`（可按品牌色检索）、`size`；默认每小时 200 次、每月 2 万次 | Pexels License：免费商用、不强制署名，但 API 条款要求「显著链接 Pexels，尽量署名摄影师」；不得暗示人物代言（[文档](https://www.pexels.com/api/documentation/)） |
| **Pixabay 视频 / 图片** | 补充实拍、插画、矢量 | `GET /api/videos/?q&video_type=film&min_width=1080`；图片 `/api/?image_type=photo&orientation=vertical&colors=`；每 60 秒 100 次；**结果须缓存 24 小时、不得长期热链** | Pixabay Content License；展示搜索结果时注明来源（[文档](https://pixabay.com/api/docs/)） |
| **Wikimedia Commons** | 真实人物、机构、历史、地标、产品实物 | `commons.wikimedia.org/w/api.php?action=query&generator=search&gsrnamespace=6&prop=imageinfo&iiprop=url|extmetadata` 取 `LicenseShortName / Artist / AttributionRequired`，不需要 key | 逐文件许可：PD、CC0 可直接用；CC BY 必须署名；**CC BY-SA 默认不用或单独标注**；含 NC、ND 的一律排除 |
| **官方页面 / 新闻页截图** | 产品官网、发布页、招聘页、论文、GitHub | 用 `gpt-5.6-luna` web_search（约 ¥0.02 次）拿带 citation 的 URL；截图增强：1080 宽手机视口、关闭 cookie 弹窗、按关键词滚动定位、元素级截图、高亮框 | 属于「引用」性质：标注来源 URL，提示「仅评论或介绍性引用，商业投放请自评」；新闻图片**不截图片本体**，只截标题区 |
| **政府开放数据** | 统计数字、趋势 | 国家统计局 data.stats.gov.cn、data.gov 等，取**数值**后用自家图表模板**重绘** | 数据事实本身无版权，标注数据来源 |

每个 beat 并行检索，合并成候选池：先用免费源，每源取 5–8 个，凑够 12 个候选后再决定要不要付费生成。

#### ③ 视觉审片打分与去重

- 把每个 beat 的候选（视频取 3 帧缩略：Pexels 返回的 `video_pictures`）**拼成一张 3×3 联系表**，一次 `gemini-3.5-flash` 视觉调用打分，每个 beat 约 ¥0.02–0.04：
  - `relevance`：must_show 是否都在、是否就是 subject；
  - `aesthetic`：构图、光线、焦点、景深；
  - `brand`：色温和饱和度是否接近项目影调；
  - `clean`：有没有水印、文字、Logo、可识别人脸的风险、明显的地域违和；
  - `tech`：分辨率、压缩块、竖构图可裁性；
  - 外加 `focal`：主体中心坐标（0–1），供裁切用。
- 规则：relevance ≥ 7 且总分 ≥ 32/40 才入选；都不达标就退到生成。
- **去重**：对已选素材算 dHash（ffmpeg 抽帧后用 64-bit 感知哈希），汉明距离 < 10 视为重复；同一个 source id 或同一个文件**全片只用一次**（直接修掉 README v3 的复用问题）；景别和主体多样性约束。

#### ④ 加工：裁切、选段、调色、运动

- **智能裁切**：按 `focal` 点计算 1080×960 或 1080×1920 裁框（主体落在三分线附近）；分辨率不够时降级成 split 或 pip，**不硬放大**。
- **视频选段**：用 ffmpeg `scdet` 剔除素材内部的剪辑点，选运动能量平稳的 2–4s；60fps 素材在 30fps 时间线上放成 0.5× 升格，24/25fps 统一转 30。
- **统一调色**：项目级一套 `.cube` LUT（暖中性、低饱和、柔高光），用 ffmpeg `lut3d` 预处理所有 B-roll，再按人物背景的平均色温做白平衡微调（复用现有的「背景色温匹配」思路）。
- **质感层**：Remotion 里叠 3–5% 的动态颗粒纹理、轻暗角（所有素材画面统一，卡片底也可以加极轻的颗粒）。
- **生图影调模板**（统一「同一个摄影师」）：`editorial product photography, soft window light from left, warm neutral palette (#EFEBE5 family), 50mm, shallow depth of field, matte film look, subtle grain, no text`，并加禁用词表：hologram、robot、neon、glowing。

#### ⑤ 授权记录与提示

每个项目一份 `credits.json`：

```json
{"file":"broll/ab12.mp4","source":"pexels","id":123456,"page":"https://www.pexels.com/video/…","author":"…","license":"Pexels License",
 "licenseUrl":"https://www.pexels.com/license/","attributionRequired":false,"aiGenerated":false,"modified":["crop","lut","speed0.5"],
 "query":"engineer client office","fetchedAt":"2026-…"}
```

- 工作台「素材来源」面板：逐条列出，可一键替换或删除；有 CC BY 或截图时显示黄色提示。
- 导出时自动生成「发布正文末尾署名」文本，例如「素材：Pexels @xxx、Wikimedia Commons（CC BY 4.0）@yyy；部分画面为 AI 生成」。
- 默认策略：排除 NC、ND、BY-SA；可识别人脸的实拍素材不用在负面语境里；不使用品牌 Logo 做装饰。

**成本估算**（2 分钟片，约 20 个 beat）：检索约 ¥0（Pexels、Pixabay、Wikimedia 免费；luna 搜 URL 约 5 次，¥0.1）+ 视觉审片约 ¥0.6 + 兜底生图 3–5 张约 ¥1 + 可选 Seedance 1 条 ¥2.4，**合计 ¥2–4**，在 ¥10 预算内。

### 5.4 呈现升级（影视飓风式具体做法）

| 手法 | 做法（Remotion 或 ffmpeg 落地） | 用在哪 |
|---|---|---|
| **全屏 B-roll 插入（A/B-roll 协同）** | 新 layout `broll`：1080×1920 素材铺满，人声继续，字幕移到 y≈1400；进入前 2 帧 J-cut（声音先到）；时长 1.5–3.5s | 口播里的具体名词、动作，比如 0:10「带进业务现场」 |
| **画中画** | 素材全屏，人物缩进右下圆角 360×480，带描边和阴影 | 讲解截图或流程时保持「人在场」 |
| **分屏升级** | 上半屏素材铺满加底部渐变压暗，信息直接排在图上（像黄金样本的钩子），不再是「米色底 + 小白卡」 | 所有带图的卡 |
| **全屏加浮层卡** | 人物全屏，顶部浮一张玻璃小卡（黄金样本 1:28–1:40 的做法） | 情绪段、总结段 |
| **Ken Burns 设计化** | 起止两个裁框由 `focal` 计算（推向主体，或沿视线方向平移），8–12% 位移，`Easing.inOut` | 所有静图 |
| **2.5D 视差** | 本地深度估计（Depth Anything V2 Small ONNX，跑在 onnxruntime 上，和 RVM 同栈）把前景和背景分两层，前景移动幅度是背景的 1.6 倍 | 钩子图、关键实物图 |
| **速度变化** | 60fps 素材升格 0.5×；剪点前 6 帧曲线加速（S6「曲线变速」），配 whoosh | 实拍 B-roll 入点和出点 |
| **统一调色** | 项目 LUT、颗粒、暗角（见 ④） | 全片 |
| **遮罩转场** | 用图形（圆、条带、卡片边缘）做遮罩擦除到下一个镜头；匹配剪辑：上一镜的圆形主体接下一镜的圆形 | 段落切换，每片 2–3 次，不滥用 |
| **标注与指示线** | 截图上 SVG 描边动画画圈或下划线（`stroke-dashoffset`），局部放大 1.6× 聚焦，标注随 Ken Burns 一起变换（S7「跟踪文字」） | browser 截图、招聘页、论文 |
| **大号数字** | bigNumber 计数滚动，配 tick 音和最后一下 hit | 0:48「3 次 5 次」 |
| **持续演进组件** | 一个组件跨 2–4 句字幕，按字幕时间逐步加行、点亮、变色（黄金样本 650 宫格、饮料对比条的做法） | 列表、对比、流程 |

## 6. 改进路线（按收益/成本排序）

### P7 第一批（必须做）

| # | 改什么 | 为什么 | 怎么验收 |
|---|---|---|---|
| 1 | **视觉节拍规划器 + 多源检索**（Pexels 视频和图、Pixabay、Wikimedia、截图；生图降为兜底）；B-roll 从卡片附属字段升级为独立的 beats | 差距 #1：try2 的 B-roll 是 0%；只取 1 个候选、只有生图 | try2 重跑（断网生图也不影响免费源）：摄影级画面占片长 ≥ 25%；实拍视频 ≥ 3 段；每个素材都和口播具体名词对得上（人工抽查 10 个，命中 ≥ 8） |
| 2 | **视觉审片打分 + 去重**（3×3 候选联系表、一次调用、focal 点；dHash 去重；全片同一素材只用一次） | 现在没有挑选环节，语义错配和复用都发现不了 | README v3 的复用不再出现；所有入选素材 relevance ≥ 7；审片花费每片 ≤ ¥1 |
| 3 | **新版式：全屏 B-roll 插入、画中画、全屏加浮层卡** | B-roll 只能关在上半屏；缺 A/B-roll 协同 | 2 分钟片里 broll 全屏 ≥ 4 次、单次 1.5–3.5s；字幕位置正确；人声连续无跳变 |
| 4 | **分镜多样性和版面约束**：同一模板连续 ≤ 2；evidenceList ≤ 20% 时长；2 分钟内 ≥ 4 种呈现模式（S2）；卡片垂直居中、放大字号，上半屏空白率 ≤ 35%；徽章语义校验（「证据」必须有来源或数据） | 差距 #2：43% 时长是 evidenceList，空白率 55% | 整片自检：模板分布、空白率、徽章检查通过；try2 重跑后 0:37–0:55 不再是 3 张同版式 |
| 5 | **钩子重做**：hook 必须有画面（素材、视频或大数字之一，否则用本地图形兜底）；第 0 帧内容完整（入场动画从「已有内容」开始，不从空白开始）；支持来源背书标签 | 差距 #3：S1 要求 8 秒内给核心画面 | 抽第 0、15、45、90 帧：标题完整可读、有视觉主体；没有纯黑或纯米色帧 |
| 6 | **卡间无空档与持续演进**：相邻卡片交叉过渡（前一张退场和后一张进场重叠 ≥ 0.15s）；新增「演进」机制：一个组件跨多句字幕逐步展开 | 差距 #4：静止段合计 62s，卡与卡之间闪空白 | 上半屏静止 > 3s 的合计 ≤ 25s（黄金样本 20s）；任何时刻上半屏空白率 ≤ 80% |
| 7 | **统一调色与质感层**：项目 LUT（ffmpeg lut3d 预处理素材）+ 白平衡匹配人物背景 + 3–5% 颗粒 + 轻暗角；生图影调模板加禁用词 | 冷暖两个色彩世界、灰白无影像感 | 素材与人物背景的平均色温差 ≤ 500K；B-roll 区平均饱和度在 35–60；盲测 3 人认为「像同一部片」 |
| 8 | **声音设计升级**：引入 whoosh、hit、riser、底噪分层（CC0 或可商用免署名音效包）；按动作类型映射（全屏插入用 whoosh，大数字用 tick 加 hit，钩子用 riser 加 hit，片尾用 Logo 音效）；同一个音效全片 ≤ 6 次 | 差距 #5：23 次同一个 UI 提示音 | 音效清单里不同音效 ≥ 5 种；同一音效 ≤ 6 次；音效和画面动作偏差 ≤ 2 帧 |
| 9 | **片尾**：最后一句字幕说完后留 ≥ 0.6s，接 2–3s 品牌片尾（可配置文字或 Logo 加音效）；CTA 提前到倒数第 5–8 秒 | 「可以联系我」被截断，没有收束 | 最后一句之后至少 0.6s 余量；片尾 3 秒响度 ≤ -18 LUFS；CTA 不和最后一句话同时出现 |
| 10 | **授权记录与提示**：`credits.json`、工作台「素材来源」面板、发布正文署名、AI 生成标识 | 引入外部素材后必须可追溯 | 每个外部素材都有 license 和 author 字段；含 NC、ND 的被过滤；导出正文自动带署名 |
| 11 | **整片级自检**（`src/qa` 新增，指标就是本报告第 1.1 节的那些）：静止时长、空白率、模板分布、B-roll 覆盖率、首帧非空、同一素材复用、音效重复；不达标就局部重做 | 现在的自检只看单卡，整片问题没人管 | 本报告的度量脚本进入自检；try2 和 README 样片能被正确判为不合格，重做后通过 |

# P4 自检与花费 · 验收记录（2026-10-15）

## 1. 结论
出片流程现在会记账，也会自查：
- **记账**：每次调用模型都按实际用量记一笔。对话类按输入、输出 token 和平台价格表计算；生图和视频按任务回报的花费记，没有回报时按估价记。花费超过上限前停止花钱的步骤，只做降级（少生一张图、不重写卡片），不中断出片。
- **预估**：开始前按时长给出一个区间，逐项列出剪口误、字幕校对、分镜、B-roll、封面、卡片自检。
- **卡片自检**：每张信息卡渲染三帧（开头、中点、结尾），交给 Gemini 从版式、层级、动效、品牌四个维度打分，不合格的重写，最多两次。
- **成片硬检查**：分辨率、帧率、响度、真峰值、黑帧、字幕安全区、配色对比度，7 项不合格只报告、不报错。
- **余额不足**：直接报错并给出充值链接，不再悄悄降级。
- **网络**：中断时最多重试 4 次（间隔 2、5、10 秒）。为避免重复扣费，提交生图/视频任务只在「连不上」时重试，其余错误直接失败。

5 个任务逐个审查和修复，最后做了整分支终审并修复了全部问题。

## 3. 发现并已修复
- **开场卡被误判**：开场 hook 卡按设计是黑底配荧光黄绿，但自检规则写死了「米色底白卡」，前两张卡的品牌分只有 5，白白重写了 3 次。规则已改为按模板判断（hook 卡和终端卡的深色底不扣分）。
- **余额不足时悄悄降级**：之前余额不足会被当成普通失败，出片照常完成，只是缺内容。现在直接报错，并提示去可想 AI 充值。
- **封面突破上限**：封面每次生图前都检查剩余预算。

## 4. 已知限制
- 自检用三帧静图判断动效，只能看出「有没有在推进」，看不出缓动曲线好不好。
- 卡片重写最多两次，3 张卡重写后仍不到 8 分，按最好的一版出片。

这次试跑时代理短暂断线，B-roll 的 3 张生图和 1 张卡片的自检都报 `fetch failed`。当时用的是修复前的代码，不会重试。
